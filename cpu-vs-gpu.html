BEGINNER MODE · SAME WORKLOAD, DIFFERENT ARCHITECTURE

How a CPU and GPU execute the same work

Start with one simple calculation and watch how the execution style changes. The goal is not “CPU is sequential, GPU is parallel”; modern CPUs are parallel too. The key difference is how each architecture balances latency, control flow and throughput.

1. Start with one problem

We want to calculate:

C[i] = A[i] + B[i]

For eight elements:

A = [1, 2, 3, 4, 5, 6, 7, 8]
B = [2, 4, 6, 8, 10, 12, 14, 16]

Every element uses the same kind of operation. That makes this a good example for understanding parallel throughput.

3. What should you learn?

CPU

Strong for low-latency work, complex control flow, operating-system tasks and workloads where instructions are not all alike.

GPU

Strong for high-throughput workloads where many threads perform similar operations on independent data.

Important correction

Do not memorize “CPU = sequential, GPU = parallel.” CPUs also exploit instruction-level, thread-level and vector parallelism. GPUs simply put much more of their design emphasis on throughput.

Technical vocabulary — after you understand the picture

CPU: cores, pipeline, cache, SIMD/vector execution, branch prediction and out-of-order execution.

GPU: many threads, thread groups/warps or wavefronts, high-throughput execution and high memory bandwidth.

Situated-learning connection: You are not only reading “parallelism.” You are applying the same workload to two execution models and observing why the architecture matters.
