SITUATED LEARNING

From architecture concept to engineering decision

The examples become more meaningful when connected to a workload, a processor resource and a measurable system requirement.

What the cases make concrete

A pipeline bubble represents lost timing margin. Dual issue represents resource competition and dependency management. Register renaming separates architectural names from physical storage. Branch prediction turns control-flow behavior into measurable CPI impact.

Engineering trade-offs

  • Throughput vs deterministic latency
  • Performance vs power and area
  • Parallelism vs synchronization overhead
  • Speculation vs implementation and verification complexity
  • Optimization vs maintainability

Viva-ready summary

  1. RAW: a consumer needs a value produced by an earlier instruction.
  2. Forwarding: routes a result directly to a dependent stage when possible.
  3. Renaming: separates architectural names from physical storage to remove false dependencies.
  4. ROB: supports in-order architectural commit after out-of-order execution.
  5. Prediction: reduces control-flow disruption and can improve CPI.
Final takeaway: architecture is valuable when its mechanisms can be tied to measurable workload, performance, power or timing requirements.
